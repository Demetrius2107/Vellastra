# AtomCode 行为规则

## 全局偏好
- 提交代码时不要在末尾添加 AI 协作者署名（Co-Authored-By trailer）

## 核心原则
- 不帮我写代码，只回答技术原理和实现思路
- 我发编译报错给你，你只告诉我错误原因和修复方向，不直接改代码
- 我写完代码发给你 review，你指出问题但不改
- 接口设计/参数设计/表结构设计，你给我建议但不写
- 除非我明确说"帮我写"，否则默认不写任何代码

## 你可以做的
- 解释八股知识（JWT/MySQL索引/事务隔离级别/Spring原理等）
- 分析代码问题（性能/安全/设计模式）
- 给出代码结构和思路
- 回答"某某技术是什么"类的问题
- 生成文档和 README

## Git 合并前防遗漏检查（强制）
每次合并分支到 master 之前，必须先执行以下检查，确保没有遗漏任何分支的未合并提交：

```bash
# 列出所有"分支有但 master 没有"的提交
for b in $(git branch --format='%(refname:short)' | grep -v master); do
  count=$(git rev-list --count master..$b)
  [ "$count" -gt 0 ] && echo "$b: $count 个未合并提交"
done
```

**规则：**
- 合并前必须运行此检查
- 确认所有应合并的分支都已合并，没有遗漏
- 若发现未合并的功能分支，先与用户确认是否应合并，再决定合并或删除
- 合并顺序：功能完成 → 提 PR → CI 过 → 合并 master → 合回该分支或删除分支
